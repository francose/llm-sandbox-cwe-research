Syscall-Boundary Containment · Empirical Evaluation

Can a seccomp argument-inspection gate contain an LLM agent?

We evaluated the control, not the model. The gate's verdict is deterministic — and that is exactly the trap: determinism is not soundness. Under an adversary the argument-inspection gate is bypassable, its coverage is incomplete, and behavioral profiling of the agent does not substitute for it.

The setup

One trust boundary, two threat sources

The control under test is a seccomp user-notification gate (rootful) that intercepts syscalls from untrusted agent-generated code, reads their pointer arguments out of the target's memory, and decides allow / deny at the syscall boundary. It is meant to contain both an attacker-injected agent (prompt injection) and an agent that malfunctions on its own (autonomous destructive shortcut).

Headline finding · EXP-11

The argument-inspection gate is bypassable

The gate blocks the persistence write perfectly when hit head-on. Wrap the identical write in a two-thread race and it walks through — because the kernel re-reads the argument after the supervisor already approved it.

Attack: write to ~/.ssh/authorized_keys through the gate

Root cause — TOCTOU on the allow path.
1. supervisor reads the path from /proc/pid/mem → sees a benign path → allow
2. supervisor returns SECCOMP_USER_NOTIF_FLAG_CONTINUE
3. kernel re-reads the pathname pointer to run the syscall — a sibling thread has swapped it to authorized_keys
The kernel manual warns against CONTINUE for security-relevant argument inspection. Existence of the bypass is host-independent; the rate is scheduler-dependent. Not fixable by a blocklist patch — the second read must be removed.

Coverage gaps · threat-model relevant

Even when it isn't raced, the boundary leaks

Two forces do not reduce to one footprint P4 · refuted

Injection reaches its goal 100% via execve; autonomous destruction is 82% execve but 18% direct unlink / rmdir — a path injection never takes. An execve/connect-only gate misses that 18% of self-driven destruction outright. Footprint is set by mechanism, not force.

The blocklist is structurally incomplete P8 · refuted

Verified escapes at the ABI: io_uring (one unblocked io_uring_setup submits connect/openat/write/unlink as ring ops that never hit syscall-entry seccomp), open / openat2 / creat, UDP sendto / sendmsg, and i386 / x32 compat syscall numbers. Absolute completeness needs a default-deny allowlist, not a blocklist.

Selectivity sits on a false-positive / evasion trade-off EXP-12

The gate is genuinely selective — it is not deny-all (it allows benign writes). But it matches paths with strstr tokens: un-anchored tokens (cron, authorized_keys) false-positive on benign lookalikes, while anchored tokens are evaded by path normalization. It cannot be both precise and evasion-resistant without real canonicalization.

What holds

The boundary is still the right place to watch

The findings are not "give up on the syscall boundary" — the boundary is sound as an observation point. The problem is treating a deterministic verdict as a sound one.

Output/static analysis cannot certify P9 · holds

10 of 10 detectors — static analyzers and AddressSanitizer included — miss an intra-object overflow that crosses no kernel boundary. You cannot certify from the artifact; you have to watch execution.

Interception is language-invariant P12 · holds

The same shell-spawn written in C, Python, and shell is denied identically (denied_execve=1 each) — the gate is agnostic to the language that emitted the call.

The verdict is deterministic P5 · holds (narrow)

Zero variance across repeats — but that is definitional, not protection. Deterministic ≠ sound. This is the core reframe: certify the gate's verdict, never claim it certifies against harm.

Dead ends · so the team doesn't chase them

Profiling the agent's behavior does not gate

We tested three "detect the bad agent by how it behaves" ideas. All fail as controls against an adversary — a manipulated agent chooses its own behavior. Keep them as forensics only.

Timing / cadence attribution P14c · refuted

A dumb random-sleep script is statistically indistinguishable from a live agent (CV 0.45 vs 0.54; 15/17 intervals overlap). Raw timing cannot tell human from script from agent.

Stated-intent vs. footprint divergence P13 · demoted

Weak and injection-confined (22% / 0% / 0%), and a manipulated agent writes a faithful malicious rationale to drive it to zero. Non-adversarial models mostly narrate honestly, so there is little to catch.

Reaction to denial P14g · demoted

A denied agent adapts 90%, repeats 10%, stops 0% — it escalates (sudo → su → tee → alt-path) toward the same goal. The operational lesson: denial elicits enumeration, not deterrence.

Bottom line

For the threat model

What this changes about how we contain agents

  1. Detection can't certify → watch at the syscall boundary. Output/static analysis misses in-process harm; the boundary is the right observation point, and it is language-invariant.
  2. The boundary gate is deterministic but not sound. It is bypassable (TOCTOU), incomplete (io_uring, unlink/rmdir, open/creat, UDP, cross-arch), and its argument matching trades false positives against evasion.
  3. Coverage is the residual risk, not variance. Attacker- and self-driven behavior overlap on execve but do not collapse to one footprint, and a blocked agent enumerates alternatives. What protects is coverage of the union of mechanisms — not the control's determinism, and not behavioral profiling of the agent.
Do not sell a deterministic gate as "certified containment." Certify the verdict; scope the coverage; assume the agent will route around any single blocked path.
